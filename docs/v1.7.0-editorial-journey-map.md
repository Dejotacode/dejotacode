## Conteúdos publicados fora das trilhas

### Como estudar tecnologia sem se perder em cursos e ferramentas

Slug: `como-estudar-tecnologia-sem-se-perder`
Categoria: `tecnologia-pratica`

Função editorial atual:

- página de orientação para iniciantes antes da escolha de uma trilha;
- ponte natural para a trilha `Linux do zero` quando o foco é sistema e terminal;
- ponte natural para conteúdos iniciais de web quando o objetivo é programação.

O conteúdo já possui links contextuais para:

- `como-a-web-funciona`;
- `primeiro-site-html-css`;
- `/trilhas/linux-do-zero/`.

Decisão nesta etapa: manter fora das trilhas e preservar o CTA de conversão atual até existir baseline suficiente.

### Como escolher seu primeiro projeto de portfólio

Slug: `escolher-primeiro-projeto-portfolio`
Categoria: `programacao`

O conteúdo já possuía link contextual para `git-e-github-entenda-a-diferenca`.

Na v1.7.0, o linking editorial foi reforçado com:

- `/trilhas/primeiros-passos-programacao/`, para leitores que ainda estejam construindo os fundamentos;
- `/portfolio/`, como exemplo de projeto apresentado com problema, decisões, arquitetura e aprendizados.

Função editorial:

- continuação natural após a trilha de programação;
- ponte entre aprendizado técnico e portfólio;
- candidato futuro a etapa opcional pós-trilha, não obrigatória.

Decisão nesta etapa: não adicionar à trilha ainda, porque isso mudaria a sequência e o comportamento de conversão medido por `trail_*`. O CTA principal do artigo também permanece inalterado.

## Leitura do inventário

A base publicada possui 17 conteúdos editoriais identificados no build atual. Quinze fazem parte diretamente das quatro trilhas e dois permanecem fora delas com funções editoriais complementares.

Isso indica que a prioridade imediata não é criar uma quinta trilha. O ganho mais provável está em reforçar continuidade entre:

- orientação inicial → escolha de trilha;
- conclusão da trilha de programação → primeiro projeto;
- artigos fora de trilha → guia/newsletter;
- páginas de categoria → trilhas relacionadas.

## Regras para futuras mudanças

Antes de alterar destinos ou copy de CTAs:

1. registrar baseline de `page_view`, `cta_click`, `form_start` e `lead_submit`;
2. alterar uma variável relevante por vez;
3. preservar nomes de eventos para comparação antes/depois;
4. não transformar artigos em etapas de trilha apenas para aumentar métricas de conclusão;
5. priorizar coerência pedagógica sobre volume de páginas.

## Candidatos para experimentos posteriores

Somente após baseline quantitativa:

- testar uma continuidade pós-trilha de programação para `escolher-primeiro-projeto-portfolio` como elemento de navegação da trilha, não apenas link editorial no artigo;
- revisar páginas de categoria para destacar a trilha mais relacionada quando houver correspondência clara;
- comparar CTR e progressão antes/depois sem introduzir identificação individual.
