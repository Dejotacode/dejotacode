# Protocolo de medição pós-release — v1.7.0

## Objetivo

Definir janelas, consultas e cálculos reproduzíveis para o baseline quantitativo da v1.7.0 sem alterar conversão durante a coleta.

## Semântica temporal

A API grava `metric_date` com `new Date().toISOString().slice(0, 10)`. Portanto, os buckets diários são datas UTC.

O endpoint administrativo atual resume os últimos 30 dias e não oferece parâmetros de janela. Para D+7 e D+14, use consultas D1 somente leitura com limites explícitos.

## Janelas oficiais

A release v1.7.0 foi publicada em 2026-09-16. Para snapshots reproduzíveis:

- D+7: `metric_date >= '2026-09-16' AND metric_date < '2026-09-23'`;
- D+14: `metric_date >= '2026-09-16' AND metric_date < '2026-09-30'`.

A primeira data é parcial porque a release ocorreu durante 2026-09-16. Essa limitação deve acompanhar qualquer interpretação.

## Eventos

Coletar: `page_view`, `cta_click`, `form_start`, `lead_submit`, `guide_access`, `trail_start`, `trail_lesson_click` e `trail_complete`.

`contact_submit` pode ser registrado separadamente, mas não entra no funil principal de conteúdo → trilha/guia → newsletter.

## Consulta base

Execute a partir de `Dejotacode/dejotacode-api`:

```bash
npx wrangler d1 execute DB --env production --remote --command "SELECT event_type, SUM(total) AS total FROM daily_metrics WHERE metric_date >= '2026-09-16' AND metric_date < '2026-09-23' GROUP BY event_type ORDER BY event_type;"
```

No D+14, substitua apenas o limite superior por `2026-09-30`.

## Segmentação complementar

Para investigar sem mudar a hipótese, agregue por `path` e, quando existir, por `campaign`. Não copie dados pessoais para issues ou documentação.

## Cálculos

- CTA CTR = `cta_click / page_view`;
- conversão em lead = `lead_submit / page_view`;
- lead após início de formulário = `lead_submit / form_start`;
- conclusão de trilha = `trail_complete / trail_start`.

Quando o denominador for zero, registrar `N/A`, não `0%`.

## Regra de decisão

Não escolher experimento de CRO antes do D+7. No D+7, só formular hipótese se houver volume suficiente para evitar leitura enganosa. O D+14 serve para confirmar, refutar ou manter a hipótese antes de ampliar mudanças.

Durante a janela, preservar nomes de eventos, campanhas e CTAs. Mudanças operacionais/documentais sem efeito no funil podem continuar.

## Evidência mínima

Registrar data/hora da extração, janela UTC, consulta executada, totais por evento, razões calculadas, principais paths/campaigns relevantes e limitações de amostra.
