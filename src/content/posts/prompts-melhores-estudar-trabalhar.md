Um bom prompt não precisa ser longo. Ele precisa reduzir ambiguidades suficientes para que a ferramenta entenda a tarefa.

## Comece pelo objetivo

Em vez de escrever apenas “explique Git”, diga o que você quer conseguir:

```text
Explique Git para alguém que nunca usou controle de versão.
Quero entender commit, branch e push antes de praticar no terminal.
```

## Adicione contexto útil

Contexto ajuda quando muda a resposta. Informe seu nível, ferramenta, restrição ou resultado esperado.

```text
Estou estudando JavaScript há uma semana e já entendo variáveis e funções.
Crie 5 exercícios curtos sobre condições, do mais simples ao mais difícil.
```

## Defina o formato

Se você precisa revisar rápido, peça tabela. Se precisa executar, peça passos. Se está aprendendo, peça explicação seguida de exercício.

Um modelo simples é:

1. tarefa;
2. contexto;
3. restrições;
4. formato desejado.

## Peça critérios, não só respostas

Para decisões, pergunte quais critérios foram usados. Isso facilita revisar o raciocínio e discordar quando necessário.

```text
Compare duas abordagens para este problema.
Explique vantagens, limitações e quando cada uma faz sentido.
Não escolha por mim.
```

## Itere com base no resultado

Prompting é conversa. Se a primeira resposta estiver genérica, diga o que faltou. Se estiver avançada demais, peça uma versão mais básica com exemplo concreto.

## Evite dois erros comuns

O primeiro é tentar colocar dez tarefas diferentes no mesmo pedido. O segundo é tratar a resposta como verificada só porque veio bem escrita.

A clareza melhora a utilidade, mas não elimina erros factuais.
